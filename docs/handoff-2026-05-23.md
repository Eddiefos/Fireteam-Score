## Track 2 — Dismissed rounds still showing in fireteam view (bug fix)

### Problem
Dismissing a round from personal history (inserts into `round_dismissals`) hid it from the user's own history but not from the fireteam's recent rounds list. Dismissed rounds showed as "Unknown course" because the course had been detached.

### Fix

**`src/services/fireteams.ts`** — `getFireteamRoundsWithData` now accepts `userId` as a second parameter and parallelises a `round_dismissals` fetch alongside the rounds fetch. Dismissed round IDs are filtered out before players and scores are fetched.

**`src/hooks/useFireteam.ts`** — `refresh` now passes `userId` to `getFireteamRoundsWithData(ft.id, userId)`.

## Track 3 — Owner leave / fireteam disband

### Problem
Only non-owners could leave a fireteam. If all members left, an ownerless empty fireteam would linger in the database.

### Migration applied
`supabase/migrations/20260523000000_fireteam_owner_leave.sql` — **already applied to Supabase**:
- Adds `DELETE` RLS policy: owner can delete their fireteam row
- Changes `rounds.fireteam_id` FK to `ON DELETE SET NULL` so deleting a fireteam detaches its rounds (was previously blocking the delete)

### Code changes

**`src/services/fireteams.ts`** — added `deleteFireteam(fireteamId)` which deletes the fireteam row (cascades to `fireteam_members`).

**`src/hooks/useFireteam.ts`** — `leaveFireteam` callback checks `members.length <= 1`. If last member: calls `deleteFireteam`. Otherwise: calls the normal member-removal leave.

**`src/screens/FireteamScreen.jsx`** — Leave button now shows for owner and non-owner alike. Button label is "Disband Fireteam" when the owner is the last member. Confirm modal title/body/label update to match.

## Track 4 — Code review (same session, branch: code-review)

Automated review of services, hooks, screens, game logic, and migrations. **8 fixes applied. No migrations needed. TypeScript still clean.**

### Bug fixes

**`src/screens/FireteamScreen.jsx:306` — `computeHeadToHead` arguments were swapped**
The rivalry strip showed W/L from the *opponent's* perspective. `computeHeadToHead(opp.id, userId, rounds)` → `computeHeadToHead(userId, opp.id, rounds)`. Wins and losses were inverted for every rivalry card.

**`src/services/courses.ts` — N+1 query in `getCourses`**
Each call fetched all courses and then fired one extra `course_holes` query per course. Replaced with a single embedded Supabase query (`select('*, course_holes(hole_number, par, distance_m)')`). Same pattern already used in `getOfficialCourses`.

**`src/services/courses.ts` — `approveSubmission` never set `par_total`**
Courses approved from submissions had `par_total = null` even when `holes_detail` was present. Now computed (`holes_detail.reduce((sum, h) => sum + h.par, 0)`) and inserted.

**`src/services/rounds.ts` — secondary query errors silently swallowed**
`getRounds` and `getPlayerRoundsWithData` destructured errors from `round_dismissals`, `round_players`, and `scores` queries but never threw. Errors would silently produce empty datasets. Added `if (error) throw` for each.

**`src/lib/gameLogic.ts` + `src/screens/StatsScreen.jsx` — player matched by `displayName` instead of `userId`**
`computePlayerStats` and `StatsScreen`'s `myRounds` memo both looked up the current player by `displayName`. If a user renames themselves, all historical stats silently break (player is found in new rounds but not old ones). Changed `computePlayerStats(rounds, playerName)` → `computePlayerStats(rounds, playerUserId)` and updated all call sites to match on `p.userId`. Display name is still used in StatsScreen for the greeting heading (`displayName` variable).

### Best practice fixes

**`src/App.jsx:142` — `go` callback had stale `[screen, params]` deps**
The function body never reads `screen` or `params` — it only calls `setScreen`/`setParams`. Those deps caused `go` to be recreated on every navigation, unnecessarily invalidating any `useEffect` depending on it. Changed to `[]`.

**`src/screens/LiveScorecardScreen.jsx:57` — `go` missing from `useEffect` dep array**
The effect that redirects to home when there's no active round was missing `go` from its dependency array. Fixed to `[roundsLoading, activeRound, go]`.

**`src/services/supabase.ts` — no guard against missing env vars**
`createClient(undefined, undefined)` throws a cryptic Supabase-internal error. Added an explicit check with a message pointing to `.env.local`.

### Not changed (noted for awareness)
- `getCourses` `updateCourse` deletes then re-inserts holes (non-atomic) — acceptable risk for a low-traffic admin path; would need a Postgres function to make atomic
- `useFireteam` is instantiated twice (App.jsx for badge + FireteamScreen) — two independent fetches; should be fixed when a global state store (Zustand) is added per CLAUDE.md plan
- `weather-proxy` JWT verification still OFF — known issue from Supabase anon key format, documented in memory
