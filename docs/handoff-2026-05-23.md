## Track 2 — Dismissed rounds still showing in fireteam view (bug fix)

### Problem
Dismissing a round from personal history (inserts into `round_dismissals`) hid it from the user's own history but not from the fireteam's recent rounds list. Dismissed rounds showed as "Unknown course" because the course had been detached.

### Fix

**`src/services/fireteams.ts`** — `getFireteamRoundsWithData` now accepts `userId` as a second parameter and parallelises a `round_dismissals` fetch alongside the rounds fetch. Dismissed round IDs are filtered out before players and scores are fetched.

**`src/hooks/useFireteam.ts`** — `refresh` now passes `userId` to `getFireteamRoundsWithData(ft.id, userId)`.

## Track 3 — Owner leave / fireteam disband

### Problem
Only non-owners could leave a fireteam. If all members left, an ownerless empty fireteam would linger in the database.

### Migration applied
`supabase/migrations/20260523000000_fireteam_owner_leave.sql` — **already applied to Supabase**:
- Adds `DELETE` RLS policy: owner can delete their fireteam row
- Changes `rounds.fireteam_id` FK to `ON DELETE SET NULL` so deleting a fireteam detaches its rounds (was previously blocking the delete)

### Code changes

**`src/services/fireteams.ts`** — added `deleteFireteam(fireteamId)` which deletes the fireteam row (cascades to `fireteam_members`).

**`src/hooks/useFireteam.ts`** — `leaveFireteam` callback checks `members.length <= 1`. If last member: calls `deleteFireteam`. Otherwise: calls the normal member-removal leave.

**`src/screens/FireteamScreen.jsx`** — Leave button now shows for owner and non-owner alike. Button label is "Disband Fireteam" when the owner is the last member. Confirm modal title/body/label update to match.
