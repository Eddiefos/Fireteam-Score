## What was fixed

### Orphaned rounds: white screen / redirect to home

**Problem:** Tapping an orphaned round card (course deleted → `course_id = NULL`) caused an instant white screen.

**Root cause chain:**
1. `RoundDetailScreen.useMemo` returned `null` when `pars.length === 0` (no course → no pars)
2. `useEffect` saw `!round` → called `go('home')` — instant redirect
3. The real crash was `useToast()` being called **after** the early `return` guard — a React Rules of Hooks violation → white screen before the redirect even fired

**Fix (`src/screens/RoundDetailScreen.jsx`):**
- Moved `useToast()` to the top of the component with the other hooks
- Removed `if (!pars.length) return null` from the `useMemo` — hole count is now inferred from actual score rows when pars are unavailable: `max(s.hole_number)` across scores
- `useEffect` now redirects only when `rawRound` is missing (the round itself was deleted), not when the course is missing
- Orphaned rounds render a degraded-but-functional view: ⚠️ banner, player totals (no par-relative chips), no scorecard grid, delete button still works

### "Deleted course" label

**Problem:** Orphaned rounds showed "Course" (HomeScreen) and "Unknown course" (FireteamScreen) — generic fallbacks that gave no context.

**Fix:**
- `src/screens/HomeScreen.jsx`: `r.course_id === null ? 'Deleted course' : courses.find(...)?.name || 'Course'`
- `src/services/rounds.ts` (`getPlayerRoundsWithData`): `r.courses?.name ?? (r.course_id === null ? 'Deleted course' : 'Unknown course')`

### Round deletion was hard-deleting for all players

**Problem:** The trash icon called `deleteRound` (hard `DELETE`) — one shared row, so the round disappeared for every participant.

**Fix:** Replaced with a per-user **dismissal** system:

- New table `round_dismissals (round_id, user_id)` — one row per person who hides the round
- `dismissRound(roundId, userId)` inserts a dismissal row; the `rounds` row is never touched
- `getRounds` and `getPlayerRoundsWithData` both filter out dismissed rounds, so history and stats reflect each user's own view independently
- Other players are completely unaffected
- Modal text updated: "This round will be removed from your history and stats. Other players won't be affected — they'll still see their copy."

### Silent delete failure (no feedback)

**Problem:** `handleDelete` had no try/catch. If the DB rejected the call, the modal closed and nothing happened — no error shown to the user.

**Fix:** `handleDelete` now catches errors and calls `toast.show('Could not remove round. Try again.')` — `toast.node` is rendered alongside `RoundDetailImpl`.

### RLS: any round player can now delete (hard delete)

Added `supabase/migrations/20260520000001_round_delete_any_player.sql`:
```sql
drop policy if exists "Round creator can delete" on rounds;
create policy "Round creator or player can delete" on rounds
  for delete using (auth.uid() = created_by or is_round_player(id));
```
This was needed for the (now replaced) hard-delete path. It's still in place and harmless — `dismissRound` doesn't need it, but the policy is correct if a hard delete is ever needed.
