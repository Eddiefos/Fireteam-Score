## RLS fixes (Supabase SQL editor — applied manually)

### is_round_player SECURITY DEFINER function
Created to break the `round_players` ↔ `rounds` ↔ `scores` recursion chain:
```sql
create or replace function is_round_player(rid uuid)
returns boolean as $$
  select exists (select 1 from round_players where round_id = rid and user_id = auth.uid());
$$ language sql security definer stable;
```

### Nuclear policy rebuild (rounds, round_players, scores)
All old policies on these three tables were dropped via a DO block and recreated cleanly:
- `rounds_select`: `created_by OR is_round_player(id) OR is_fireteam_member(fireteam_id)`
- `rounds_insert`: `created_by`
- `rounds_update`: `created_by`
- `round_players_select`: `is_round_player(round_id)`
- `round_players_insert`: round creator check via `rounds`
- `scores_select`: `is_round_player(round_id) OR created_by`
- `scores_insert` / `scores_update`: `user_id OR created_by`

### Migration 20260519000002_course_fk_and_policies.sql (new file)
- Changed `rounds.course_id` FK from hard-fail to `ON DELETE SET NULL` — fixes the 409 error when deleting a course that has rounds referencing it
- Added DELETE policy on `courses` for creator
- Added full CRUD policies on `course_holes` for the course creator
- Added SELECT policy on `course_holes` (readable when parent course is public or owned)

## Bug fixes (code)

### Resume card never appeared for Player B (Mats)
- Root cause: `getActiveRound` selected fields but omitted `status`, so `activeRound.status === 'active'` was always `undefined === 'active'` → false
- Fix: added `status` to the select in `src/services/rounds.ts`

### Resume card stayed after host finished round
- Root cause: `useRounds` had no realtime subscription — Mats's screen never knew the round was finished
- Fix: added a Supabase postgres_changes `UPDATE` subscription to `src/hooks/useRounds.ts` that calls `refresh()` when any round updates

### finishRound didn't update holes_played
- Fix: `finishRound(roundId, holesPlayed)` now also sets `holes_played` in the DB
- Updated signature in `src/services/rounds.ts` and `src/hooks/useRounds.ts`

### No "Finish Round" button
- Fix: `LiveScorecardScreen` computes `allDone` (all players scored all holes) and shows an orange "Finish Round →" button at the bottom — but only for the round creator (`isCreator`)
- Confirmation modal always appears before finishing
- Hamburger menu gains a "Finish round early…" option for the creator when not all holes are done, with a warning-styled confirm dialog

### Host couldn't enter scores for players who hadn't scored yet
- Root cause: the "—" placeholder for other players was a plain `div`, not clickable
- Fix: when `isCreator && !isMe && !hasScore`, the "—" is now a tappable button that opens the inline number picker

### Stats screen showed "No rounds yet" always
- Root cause 1: `StatsScreen` called `useRounds` which returns basic metadata — no `players` or `scores` arrays
- Root cause 2: player match used `p.name` instead of `p.displayName`
- Fix: new `src/hooks/usePlayerRounds.ts` and `src/services/rounds.ts → getPlayerRoundsWithData()` — fetches finished rounds with players + scores assembled (3-query pattern, same as `getFireteamRoundsWithData`), filtered to rounds where the current user is a player
- Fix: replaced `p.name` → `p.displayName` in `StatsScreen`

### Courses scoping (what each screen shows)

| Screen | Behaviour | onlyMine |
|---|---|---|
| CoursesScreen (manage tab) | Only your created courses | `true` |
| StartRoundScreen | Only your created courses | `true` |
| HomeScreen count | Only your created courses | counted via `c.created_by === userId` filter |
| HomeScreen name lookup | All accessible (for shared round names) | `false` |
| LiveScorecardScreen | All accessible (host's course must be found) | `false` |
| RoundDetailScreen | All accessible | `false` |

Previously `getCourses` always filtered to `created_by = userId`. This was changed to support an `onlyMine` flag so each screen can opt in or out.

### Rival card showed wrong W/L direction
- Root cause: rivalry computed `computeHeadToHead(userId, opp.id)` = YOUR record against opponent, but card showed opponent's avatar → looked like opponent's record
- Fix: flipped to `computeHeadToHead(opp.id, userId)` → card now shows the opponent's record against you ("Eddie: 1W / 0L" = Eddie has beaten you once)

### Course deletion 409 error
- Root cause: `rounds.course_id` had a hard FK constraint with no cascade — rounds referenced the course blocked deletion
- Fix: migration changes the FK to `ON DELETE SET NULL`; also ensured DELETE RLS policy exists on `courses`
